# Auto-Loop：多智能体科研探索

**中文版本 0.1.11 · [MIT 许可证](LICENSE)**

[快速开始](#快速开始) · [探索流程](#探索-loop-如何运作) · [安装技能](#安装技能) · [填写 Idea](#填写-ideamd) · [更新与回退](#更新与回退)

Auto-Loop 是面向 Codex 的科研探索技能。人类定义问题、材料、范围和完成标准；智能体每轮重读 Idea，从领域依据与数据关系提出假设、实现方法、检验证据，再决定继续、简化或重建。

研究重视有意义的问题、清楚的方法路径和充分证据。精度须支持实际用途，明确的性能目标仍须满足；达到要求后，不用微小提分替代核心贡献。各职责可按需多人协作，产物逐轮替换，研究认识集中在一份 LOOP。

## 快速开始

1. **安装技能。** 将[仓库地址](https://github.com/Haichuan-Zhao/Auto-Loop)发给 Codex，按下方说明安装 `auto-loop`。
2. **准备 Idea。** 在独立研究目录编写 `Idea.md`，可参考下方[输入示例](#填写-ideamd)。
3. **开始探索。** 在该目录调用 `$auto-loop`；后续更新同一份 Idea，再次调用即可续接。

各课题只共享技能，不共享研究状态。起步时可以只有一份 Idea，无需复制本仓库或准备角色配置。

## 探索 loop 如何运作

各职责可由一位或多位智能体承担。同一方案的指导与执行分离，审查者不参与被审版本；多人先形成各自判断，再按证据处理分歧。同一文件同一时刻只有一个写入者。

- **方法回应问题。** 从实际瓶颈、领域依据和观测限制形成技术路径；不同候选须有实质差异，按证据取舍，不靠拼接模块维持路线。
- **主辅任务分清。** 辅助验证足够后返回主线；下游提分不能替代上游主张，计算正确、创新依据与整体达标分别判断。
- **反馈遵守数据边界。** 冻结测试诊断不能回传选法；只凭转述、一致意见或漂亮图，不能宣布研究结论成立。
- **每轮替换产物。** 复用有效入口与公共材料，清理无用途旧文件；原始材料、明确保留项、运行及待审依赖和必要证据继续保留。

未达标且仍有获准、有依据的工作时继续；已达标、用户停止、时限或额度到达、实际阻塞时按原因收尾。单条路线失败不自动代表课题不可行。

## 安装技能

需要支持本地技能、文件读写和命令执行的 Codex 环境。多智能体协作需要相应工具；科研计算需要可执行 Jupyter notebook 的环境及课题所需依赖，无需预装所有计算框架。

将下面整段发送给 Codex：

```text
使用 $skill-installer 安装这个 GitHub 仓库中的 auto-loop。
仓库地址：https://github.com/Haichuan-Zhao/Auto-Loop
技能目录：.agents/skills/auto-loop
安装到当前 Codex 可发现的用户级技能目录，供独立课题调用。
采用仓库默认分支；我指定分支、标签或提交时采用指定来源。
已有同名技能时先核对安装来源与本地定制，按原安装方式处理。
完成后报告实际路径、metadata.version 和内容身份。本次只安装，不启动研究。
```

安装范围仅为完整的 `auto-loop` 技能目录：

```text
auto-loop/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── LICENSE
```

已使用 Skills Manager 等管理工具时，沿用其安装与部署关系。Git 来源从所记录的远程版本更新，本地导入则先更新原目录；不要让多个安装器反复覆盖同一入口。


相同版本号不证明内容相同。下载或克隆仓库本身不等于完成安装；出现多个同名技能时，须明确实际采用哪一份。

## 填写 Idea.md

在自己的研究目录创建 Idea.md，用自己的话写清动机与主问题。下面是可填写的输入框架，占位内容本身不构成研究授权：

```text
研究问题与目标：待填写对象、动机和主问题；有辅助任务时说明它验证什么。
材料与权限：待填写路径或来源、允许处理范围、已知测试使用历史。
本阶段范围：待填写固定任务，或人类指定的因素、取值与固定条件。
完成判据：待填写核心贡献所需证据、精度用途与足够条件、评价口径。
执行授权：待确认允许的工作、设备与多智能体范围；时间上限可选。
```

- 分清必须满足的要求与可被证据推翻的设想；多任务课题写清主辅关系。
- 模型、优化器和实现细节可以交给智能体，不必预列算法或完整实验套件。
- 划分、指标等技术细节可授权智能体依据问题确定，并在正式评价前固定；成功含义仍由人类明确。
- 没有现成数据时，说明是否允许寻找和获取公开材料；未知历史如实标注。
- 参考论文可注明希望借鉴的问题定义、方法依据或证据组织，不预设结果或照搬实验。

<details>
<summary><b>主辅任务示例：生成方法与下游验证</b></summary>

以下仅说明输入写法，不是默认课题或执行授权：

```text
主任务：探索数据生成方法，回答本项目所定义的生成问题。
辅助任务：用下游估计辅助检验生成数据的有效性。
探索重点：生成方法的依据与假设，以及支持生成主张的直接证据。
辅助边界：建立足以可靠验证的估计实现和固定口径，不另立估计提分目标。
不算完成：估计分数改善，但生成任务的核心问题仍未回答。
```

还可补充“即使不强调最高分，仍希望解决什么问题”“哪些误差会影响用途”。有领域线索、协作偏好或特殊交付时一并注明，无需先完成文献综述或预排团队。

</details>

## 启动、继续与运行边界

在 Codex 中打开实际研究目录，或明确提供其位置，然后发送：

```text
使用 $auto-loop，完整读取实际技能，按当前研究目录的 Idea.md 开始研究。
每轮重读 Idea，核对核心贡献、当前证据缺口、本轮取舍与足够条件。
我授权本次使用原生多智能体，各职责可按需多人协作，并保留独立审查。
在已授权设备与材料范围内推进；新增科学因素先建议，不自行展开。
逐轮替换当前产物，维护 notebook、README 和同一份 LOOP。
```

不使用多智能体时，由人类承担必要指导和独立判断；单个智能体的检查只能称为自查。各角色须完整读取同一实际技能，按授权直接核对人类原文与关键证据，无需额外角色配置。

默认由指导结合实际证据与独立审查判断是否继续。启动时会提示可设置时间上限；需要时，在 Idea 或消息中补充：

```text
本次最多运行 2 小时，包含准备、计算、分析、审查与收尾。
到时保存进展并停止；未达标时说明差距和恢复位置。
```

各轮与并行智能体共用同一截止时间，恢复不自动延长。账户额度、工具权限及人类限制始终有效；默认持续探索不代表后台常驻，也不自动创建定时任务。

修改同一份 Idea 后，可发送：

```text
使用 $auto-loop，按最新 Idea.md 整理本课题并继续。
先核对新旧范围、已有证据、实际进程与依赖，复用有效工作。
更新原入口和输出，保留必要事实并清理无用途旧产物，续写同一份 LOOP。
```

变更输入不重置测试历史、探索编号、累计消耗或有效时限；原时限已到时，继续计算须明确给出新的运行授权。

## 更新与回退

先确认实际加载路径、版本、内容身份、安装来源和本地定制，只在研究阶段边界更新。正在运行或固定待审的版本保持稳定；更新仅替换技能，不覆盖课题输入或研究产物。

- **内置安装器：** 提供同一仓库及目标分支、标签或提交，先检查旧安装与定制。遇到已有目录会停止，重复安装不等于自动更新。
- **手动安装：** 获取目标来源的完整技能，比较并保留定制后替换，再核对客户端实际加载内容。
- **管理工具：** 沿用记录的 Git 或本地来源，只更新 auto-loop，保留标识、标签、预设及部署关系。

固定标签或提交不会自动切换到下一版本；本地来源须先更新原目录。更新后重新核对加载路径与内容，未反映变化时重启 Codex。回退使用此前来源的完整技能，并核对课题兼容性；无法确认运行或待审依赖时，暂不替换共享安装。
